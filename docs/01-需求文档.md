# 桌面智能创作助手（码字工具）｜需求文档
文档版本：v2.0（重定位·激进瘦身）
日期：2026‑10‑04
项目周期：8 周 / 56 天，业余开发每日 1‑2h
技术选型：Electron 桌面壳（Vue3 + Element Plus） + Spring Boot 3.5 后端 + SQLite + 双模式模型接入（自有 API / 本地 Ollama）

> 🔵**v2.0 重定位说明（本次重写核心）**：产品本体是**给创作者好用的码字工具**，AI 是写作过程中的**赋能**（灵感 / 素材 / 续写 / 润色 / 自检），**不承担"自动化创作流水线"**。
> 因此，原 v1.x 中偏"多 Agent 智能体系统"的重型设计**整体移出 v1.0**：自研多 Agent FSM 五节点编排、写文件人工审批、本地文档 RAG 知识库、多会话隔离、Redis 快照、pgvector（详见 §6）。
> ⚠️版本锁定：Spring Boot 3.5.x + Spring AI 1.x GA（Spring AI 2.0 基于 Spring Boot 4，不兼容）。
> ⚠️AI 能力不是瘦身对象：**续写、快捷处理（扩写/精简/换风格/调篇幅）、大纲灵感、素材、全文自检、文体模板全部保留**。

## 1 项目概述
### 1.1 产品简介
一款**桌面码字工具**，面向个人创作者。核心是"写得顺手"：编辑体验、文档管理、防丢稿、版本留存、多格式导出。在此之上由 AI 赋能：随时可用的**续写**、选中文字快捷处理、大纲与灵感、素材收藏与插入、全文自检。

提供两套模型接入（**配置差异，非角色差异**）：
1. **自有 API 模式（联网·开箱即用·默认推荐）**：用户填入自己的第三方大模型 API‑Key，后端代理转发；密钥仅单次请求内存使用，后端不持久化。
2. **本地 Ollama 模式（离线·隐私）**：用户本机自行安装 Ollama、下载预训练模型；推理与文档全部留在本机，不向外发送。

形态：Electron 桌面单机应用 + 本地 Spring Boot 后端 + 本地数据（SQLite 单文件）。**无登录、无角色权限、无多租户。**

### 1.2 目标用户
1. 内容创作者：网文 / 自媒体 / 公文写作者，需要长文写作、续写、素材整理。
2. 需要灵感与素材辅助的个人写作者。

### 1.3 核心价值
1. **写作体验优先**：编辑器、文档管理、防丢稿、版本、导出构成工具本体。
2. **AI 随手可用**：选中即用、光标续写、灵感与素材、一键自检；AI 不阻塞写作、结果可撤销可回退。
3. **双模式可用**：联网即用 API 模式；离线本地 Ollama 模式，文档不出本机。
4. **防丢稿与交付**：实时自动缓存 + 历史版本对比回滚 + 多格式导出（txt / md / word）。

## 2 业务目标与约束
### 2.1 业务目标
1. v1.0 交付可运行完整 MVP：**写作主线 + AI 赋能闭环 + 双模式接入**。
2. AI 能力做到"随手可用、可撤销、可回退"，不打断写作心流。
3. 离线模式下数据本地流转，不依赖公网。
4. 双模式健康检测与友好降级：Ollama 不可用时置灰引导，消除"需要训练模型"误区。

### 2.2 业务约束
1. 单机部署产品，面向个人本地使用；**不做登录、不做权限体系、不做多租户**。
2. 应用**不内置、不打包大模型**；离线模式需用户手动安装 Ollama 并 pull 预训练模型，**不需要训练模型**。
3. 应用不静默安装 Ollama、不自动执行终端命令下载模型。
4. **v1.0 交付平台锁定 Windows x64（Windows 10/11）**；不提供 macOS / Linux 构建，其他平台不在 v1.0 范围内（jlink 裁剪 JRE 仅编译 Windows x64 一份）。
5. 用户第三方 API‑Key 后端绝不持久化；密钥禁止进入日志、异常堆栈、磁盘、数据库。
6. 后端为随桌面应用启动的**本地 Java 进程**，由 Electron 主进程编排生命周期；本地数据（`.db`、`agent.yml`）统一落在应用 userData 数据目录，**禁止写死相对路径**。

### 2.3 非目标（v1.0 不做）
- 账号登录、角色权限、多租户。
- 多 Agent FSM 编排、写文件人工审批、本地文档 RAG 知识库、多会话隔离。
- 云端同步、多人协作、应用商店上架与代码签名。

## 3 用户故事
### 写作核心（工具本体）
- **US‑01 写作与自动保存**：作为创作者，我要在一个顺手的编辑器里写作，正文实时自动缓存，崩溃/重启不丢稿。
- **US‑02 文档管理**：我要新建 / 重命名 / 分组 / 搜索 / 删除我的文档，关闭应用后下次还能找到。
- **US‑03 写作舒适辅助**：长文写作时我要护眼暗色，以及悬浮的实时字数统计（**当前文档总字数 / 当前选中字数**）。
- **US‑04 版本留存**：我要能手动存版，并在写坏之后对比历史版本、一键回滚。
- **US‑05 多格式导出**：我要把成品导出为 txt / md / word，且按文体给出默认格式。

### AI 赋能（保留项）
- **US‑06 AI 续写**：写作卡住时，我要在光标处让 AI 按上文语境**续写**，结果流式插入正文，不满意可一键撤销。
- **US‑07 选中文字快捷处理**：我框选一段文字后，能直接"扩写 / 精简 / 换风格 / 调篇幅"，只处理选中部分并原地替换，可撤销。
- **US‑08 大纲与灵感**：我输入零散关键点，AI 按当前文体生成结构化大纲；并给出开头 / 标题 / 灵感建议。
- **US‑09 素材收藏与插入**：我遇到的金句 / 案例 / 专业表述可以收藏，按文体归档，需要时插入正文光标处。
- **US‑10 全文自检**：写完一键自检，按文体检查重复用词 / 敏感词 / 口语化 / 逻辑问题，给出建议与替换词。
- **US‑11 文体模板切换**：写网文 / 自媒体 / 公文时一键切换文体模板，AI 提示词与默认导出随之切换。

### 模型接入
- **US‑12 双模式接入与健康检测**：我可以选择用自有 API 密钥，或使用本机 Ollama 离线推理；Ollama 不可用时选项置灰并给出安装引导。
- **US‑13 模型参数配置**：我能调"创意程度 / 单次生成字数 / 联网素材开关"，并保存网文 / 公文两套预设。

## 4 功能需求
> 优先级：P0 写作核心（工具本体，不可裁剪）＞ P1 AI 赋能（保留项）＞ P2 模型接入（支撑层）。

### 4.1 P0 写作核心模块
#### 4.1.1 编辑器
- 采用 **TipTap**（基于 ProseMirror 的富文本编辑器内核）构建正文编辑区，**不自研 contenteditable 轻量层**；由 TipTap 提供成熟的文档模型、撤销 / 重做、键盘快捷键、Markdown 输入规则与**稳定的位置映射（position mapping）**能力。
- 基础排版：标题层级、加粗 / 斜体 / 引用 / 列表；Markdown 快捷输入（如 `#` 转标题、`**` 转加粗）。
- **内容格式约定**：正文以 **HTML（`editor.getHTML()`）** 持久化；AI 调用入参、字数统计、全文自检统一使用**纯文本投影（`editor.getText()`）**；导出时由 HTML 转换为 txt / md / word。
- 实时字数统计。
- 正文输入防抖**实时自动缓存**（本地），重启应用可恢复并提示，防丢稿。
#### 4.1.2 文档管理
- 新建 / 重命名 / 分组 / 搜索 / 删除；标题与正文入库（SQLite）。
- 文档列表按更新时间排序，支持按文体 / 分组过滤。
#### 4.1.3 写作舒适辅助（纯前端）
- 护眼暗色主题（跟随系统 + 手动切换）。
- **悬浮字数统计：当前文档总字数 / 当前选中字数**（口径只依赖编辑器实时文本，不引入"当日累计"持久化数据模型），可拖拽、可隐藏，偏好存入本地。
- 打字机专注模式（输入区居中、字号放大、滚动跟随）→ **P2 有余力再做**。
#### 4.1.4 版本留存
- 手动"保存版本" + 会话结束时自动存一版。
- `doc_version` 表记录 `content_hash / content / created_at`；提供版本列表、双版本 diff、一键回滚。
#### 4.1.5 导出
- `/api/documents/{id}/export?format=md|txt|word`；word 使用 Apache POI（XWPF），**仅做结构化基础排版（段落 / 标题），不做复杂样式**。
- 默认格式按文体：网文 txt / 自媒体 md / 公文 word，前端可覆盖选择。

### 4.2 P1 AI 赋能模块
> 统一约定：AI 调用复用 ModelRouter（见 4.3）；除自检外均为**流式返回**；所有原地替换操作**可撤销 / 可回退**；**不引入多 Agent 编排状态机**。

#### 4.2.1 AI 续写 `/api/ai/continue`
- 输入：当前位置的上文（可选全文字数上限）+ 文体 + 模型参数；输出：流式续写文本。
- 前端在光标处流式插入，用户可接受 / 撤销 / 重新生成。
- 可选"续写长度"约束拼入提示词。
#### 4.2.2 选中文字快捷处理 `/api/ai/quick`
- 操作枚举：`expand` 扩写 / `condense` 精简 / `restyle` 换风格 / `wordcount` 调篇幅。
- 只处理选中文本，SSE 流式返回，默认原地替换选中段，可撤销。
- 换风格按当前文体映射提示词；字数约束拼入提示词。
#### 4.2.3 大纲与灵感 `/api/ai/outline`、`/api/ai/inspire`
- 大纲：输入零散关键点 + 文体，生成 Markdown 层级大纲（前端解析为可点击跳转的列表）。
- 灵感：按主题 / 文体给出开头、标题、情节 / 论点建议，供用户挑选插入。
#### 4.2.4 素材收藏与插入
- 选中文本快速收藏为素材；按文体（NOVEL / MEDIA / OFFICIAL / CUSTOM）归档。
- 素材增删改查、拖拽或点击插入正文光标处；长期素材入库 `material` 表。
#### 4.2.5 全文自检 `/api/ai/check`
- **规则引擎（词级，v1.0 必做）**：按文体加载检规——网文重复用词 + 敏感词；自媒体平淡词库；公文口语化词 + 格式规范正则。
- **LLM 语义检查（语义级，P2 有余力再做）**：语句平淡 / 开头无吸引力 / 逻辑断层等，交 ModelRouter 单轮判定，返回结构化问题 JSON。
- 返回 `[{type, severity, offsetStart, offsetEnd, original, suggestion, replacement}]`；前端标红 + 悬浮替换词 + 一键替换。
#### 4.2.6 文体模板
- 内置网文 / 自媒体 / 公文三套系统提示词与预设指令模板，外部化到 `agent.yml`（**启动时读取；设置页提供"重载配置"按钮，不做文件监听热加载**）。
- 支持用户自定义模板，按 genre 归档；`prompt_template` 表带 `genre` 字段。
- 切换文体影响：AI 提示词、默认导出格式、自检规则。

### 4.3 P2 模型接入模块
#### 4.3.1 ModelRouter 双模式
1. **LOCAL**：调用配置项 `ollama.base-url` 指定的 Ollama（宿主机 `127.0.0.1:11434` / 容器 `http://ollama:11434`）。
2. **USER_PROVIDED_API**：从 **POST 请求体**读取服务商 / apiKey / baseUrl / modelName，仅单次请求内存使用，日志脱敏；内置 OpenAI / DeepSeek / 通义千问 OpenAI 兼容模板，支持自定义覆盖。
- 不使用 HTTP Header 传密钥。
#### 4.3.2 Ollama 健康检测 `/api/status/local-model`
- 探测 Ollama 服务与对话模型是否可用；返回 **3 状态：`UNAVAILABLE`（服务不可达）/ `MODEL_MISSING`（服务连通但对话模型未下载）/ `READY`（就绪）**。
- ⚠️探测收敛为 3 状态的原因：仅靠 HTTP 探测**无法可靠区分"未安装 / 已安装未启动"**，故两者统一归入 `UNAVAILABLE`，UI 用统一引导话术（安装或启动 Ollama）。
- 返回推荐模型列表与 `ollama pull` 命令；内置 FAQ 明确"只下载预训练模型，不需要训练模型"。
- 拓扑差异：容器模式无法探测宿主机安装状态，`UNAVAILABLE` 引导隐藏"未安装"字样，只提示"无法连接"。
#### 4.3.3 模型参数配置
- `temperature`（创意程度滑杆 0‑1）、`maxTokens`（单次生成字数）由后端透传；字数约束拼入提示词。
- 联网素材开关：开启后快捷处理 / 续写可调用第三方搜索 API 补充实时素材（外部依赖，**P2 有余力再做**，默认关闭，未配置搜索 Key 时置灰）。
- 支持保存并切换两套预设（网文预设 / 公文预设），存本地。

### 4.4 数据持久化
- **SQLite（MyBatis‑Plus，`DbType.SQLITE`）**：`document`（文档）、`doc_version`（版本）、`prompt_template`（文体 / 自定义模板，带 genre）、`material`（素材，带 genre）四张表。
- **数据目录由 Electron 主进程指定**：主进程以 `--writer.data-dir=<userData>/data` 拉起后端（解析顺序：启动参数 → 环境变量 → `user.home` 兜底），库文件、`agent.yml` 等全部落在该目录（见 §4.5.1）；**禁止写死相对路径**，保证打包成 exe 后仍能定位。
- SQLite 为**本机文件型嵌入式数据库**：随应用本地落盘，**无需安装、无需启动独立数据库服务、无需容器**。
- **并发与事务约束（红线）**：Hikari `maximum-pool-size: 1`（SQLite 单写，多连接极易 `database locked`）；PRAGMA 在连接初始化统一设置 `journal_mode=WAL; synchronous=NORMAL; busy_timeout=5000; foreign_keys=ON`；**事务内禁止包裹网络 IO / AI 调用，禁止长事务、长读**；定时/启动执行 `PRAGMA wal_checkpoint(TRUNCATE)` 防止 WAL 文件膨胀。
- **单进程独占**：v1.0 仅允许后端单进程打开该 `.db`，**不支持多进程同时打开同一库文件**。
- **数据即本地文件**：备份 / 迁移只需复制该 `.db` 文件（详见 03 §7.4）；不存在"数据库服务未启动导致文档打不开"的故障面。
- 前端配置（含 apiKey、模型参数预设）持久化至应用本地 `localStorage`，不上传后端。
- v1.0 **不再使用 Redis**（无会话快照 / 无多会话隔离需求）。

#### 4.4.1 数据层选型权衡（SQLite vs MySQL）
> 定位：**桌面单机、单用户、无登录无多租户**。数据层只需"本机可靠落盘"，不需要网络数据库。

| 维度 | SQLite（**v1.0 采用**） | MySQL 8.0 | 结论 |
|---|---|---|---|
| 部署形态 | 单文件嵌入式，零安装零服务 | 需独立服务进程 / 容器 + 数据卷 | 与"桌面工具"形态一致，故选 SQLite |
| 运维成本 | 无端口、无账号口令、无服务守护 | 需管理连接、口令、数据卷、备份脚本 | 个人本地使用，SQLite 显著更轻 |
| 并发能力 | 单写多读（WAL 下读写不互斥） | 高并发多连接 | 单用户场景 SQLite 足够 |
| 数据安全面 | 无对外监听端口，攻击面小 | 需防止端口 / 口令泄露 | 更契合"无鉴权、仅本机"定位 |
| 备份迁移 | 复制 `.db` 或 `VACUUM INTO` | mysqldump / 数据卷快照 | SQLite 更简单 |
| 演进空间 | 多用户 / 云同步需迁移 | 原生支持多用户 | v1.2 云同步时 MySQL 是必要选项 |

> 结论：v1.0 单机单用户故选 **SQLite**；当演进为多用户 / 云同步（v1.2）时，MySQL 是必要选项，届时按上表结构平滑迁移即可。

### 4.5 Electron 桌面端模块（Vite + Vue3 + Element Plus）
1. 主窗口：文档列表侧边栏 + 正文编辑器（TipTap 内核）+ AI 工具箱（续写 / 快捷处理 / 大纲 / 素材 / 自检）+ 悬浮字数。
2. 设置页：后端地址、模型模式单选、本地模型状态卡片（**3 状态** + 一键复制 pull 命令 + "重载配置"按钮）、API 配置表单与连通性测试、写作参数区、配置导入导出。
3. Electron 主进程负责窗口 / 菜单 / 打包（electron‑builder）；`contextIsolation` 开启、`nodeIntegration` 关闭，仅通过 preload 暴露文件选择能力。
4. **禁止 EventSource，SSE 全部用 fetch + ReadableStream**；渲染进程仅访问 `http://localhost:8080`。
5. 异常处理：Ollama 不可达、密钥错误、网络断连统一转友好提示，**不展示后端堆栈**；SSE 断连自动重连。

#### 4.5.1 桌面进程编排（R1，交付关键）
> 后端为随应用启动的本地 Java 进程，须由 Electron 主进程统一编排生命周期；否则极易出现"关窗后 Java 残留、8080 被占用、二次启动失败"。

1. **拉起方式**：主进程用 `spawn(java, [...], { shell:false })` **直接拉起 java 进程**（不用 shell 包装），使 java 成为 Electron 的**直接子进程**，`child.kill()` 有效；额外引入 `tree-kill` 作保险（Windows 等价 `taskkill /T /F`），确保退出时**杀掉整棵 Java 进程树**，不留残留。
2. **启动时序**：渲染窗口先显示**启动遮罩**，主进程轮询健康接口，未就绪显示"后端正在启动，请稍候"，**禁止在就绪前直接显示编辑器**；失败显示错误与重试按钮。
3. **崩溃自愈**：监听 `child.on('exit'/'close')`，非主动退出即判定崩溃，**自动重启 + UI 提示**；多次重启失败提示用户手动排查。
4. **残留端口回收**：启动前检测 8080 是否被占用，若为上次残留进程则回收后再启动，避免端口冲突。
5. **优雅停机**：JVM 注册 `ShutdownHook`；后端暴露 shutdown 端点（**仅允许 127.0.0.1 访问**）；应用退出时**优先调用 shutdown 接口**，失败再 `tree-kill` 强杀。
6. **数据目录注入**：主进程以 `--writer.data-dir=<userData>/data` 启动后端（见 §4.4），保证打包后配置与库文件路径正确。

#### 4.5.2 运行环境与交付形态
1. **JRE 随包分发**：用 `jlink` 裁剪自定义 JRE（约 50‑90MB）打入 electron‑builder 的 `extraResources`，**不依赖用户电脑预装 JDK21**；按架构分别编译（v1.0 仅 Windows x64）。
2. **不打包 Ollama 与模型**：本地模型由用户自行安装 pull；**docker-compose 仅用于开发调试，不作为桌面交付方案**。
3. **平台声明**：v1.0 桌面安装包**仅交付 Windows x64**，macOS / Linux 不在范围内。

## 5 非功能需求
### 5.1 安全（高优先级）
1. API‑Key 仅单次请求内存；禁止写入日志、异常堆栈、磁盘、数据库；全局日志脱敏过滤器。
2. Electron 主进程与渲染进程禁止打印密钥；`contextIsolation` 开启、`nodeIntegration` 关闭。
3. 不直接透传原始模型输出作为指令，防范 prompt 注入；配置文件格式校验。
4. **本机接口鉴权（纵深防御，非唯一防线）**：后端启动生成一次性随机 `X-Local-Token` 写入 userData 文件，Electron 主进程读取后经 preload 注入渲染进程，**token 永不经过 HTTP 传输**；所有业务接口校验该请求头，不匹配返回 401；Host 头仅允许 `localhost / 127.0.0.1`（防 DNS rebinding）；CORS 禁止 `*`。
5. **威胁模型**：v1.0 面向单机可信本机环境，**只防御浏览器网页发起的跨页攻击**，不防御本机已存在恶意程序的高级攻击场景。
### 5.2 性能
1. 本地模式单轮响应受 Ollama 硬件影响，不做强制 SLA；CPU 推理需可接受。
2. SSE 流式实时推送，后端增加背压控制。
### 5.3 可靠性
1. 模型调用失败具备重试；重试耗尽返回友好错误。
2. 配置加载失败**回滚旧配置，不崩溃**。
3. SSE 断连前端自动重连；重连失败提示用户。
### 5.4 可维护性
1. 分层清晰：控制器层 / 服务层 / AI 调用层 / 存储层；AI 能力以独立 Service 提供，互不耦合。
2. 核心路径单元测试：AI 调用、文体模板、自检规则、密钥脱敏、文档版本。
### 5.5 兼容性
1. 后端：JDK21、Spring Boot 3.5、Spring AI 1.x GA；运行时由 jlink 裁剪 JRE 随桌面应用分发。
2. 前端：Electron ≥28、Vite + Vue3 + Element Plus + **TipTap（ProseMirror 内核）**；**v1.0 仅交付 Windows x64（Windows 10/11）**，macOS / Linux 不在范围内。
3. 存储：SQLite（`org.xerial:sqlite-jdbc`）；Ollama 0.1.x 以上；第三方模型兼容 OpenAI 接口协议。

## 6 v1.0 移出 / 后置（原重型设计）
> 以下为 v1.x 中偏"多 Agent 智能体系统"的设计，按"码字工具"定位**整体移出 v1.0**；其中部分作为 v1.1 可选增强保留升级路径。

| 原设计 | 处理 | 说明 |
|---|---|---|
| 自研多 Agent FSM 五节点编排（Router/Retriever/Answerer/Writer/Reviewer） | **移出** | 码字工具不需要重型状态机；AI 改为直接短链调用 |
| 写文件人工审批（human‑approval + Diff） | **移出** | 改为"替换前可撤销 / 可回退"，无需文件级审批 |
| 本地文档 RAG 知识库（SimpleVectorStore / pgvector） | **后置 v1.1** | 需要时以"素材库检索"形式回归，不作为 v1.0 主线 |
| 多会话隔离、Redis 快照持久化 | **移出** | 单机单用户，无此需求 |
| AOP 限流 / 全局配额 / 重试埋点 | **简化** | 仅保留模型调用基础重试 |
| 极简 Web 调试页面 | **保留（可选）** | 仅用于后端接口调试 |
| 配置热加载（文件监听 + 读写锁） | **降级** | 改为启动加载 + 设置页"重载配置"按钮；砍掉 WatchService 与读写锁 |

| 联网素材搜索 | **后置 P2（v1.1）** | 外部依赖，未配置时置灰 |

## 8 验收总体原则
1. 每个里程碑产出可运行可演示版本；对应 Git Tag。
2. 功能验收：写作主线顺畅；AI 能力随手可用、可撤销回退；异常场景友好降级；无原始堆栈抛给前端。
3. 安全验收：密钥泄露专项测试；日志脱敏检查。
4. 文档验收：README、部署文档、FAQ 完整；全部文案删除"训练模型"错误表述。
5. 部署验收：**Windows x64 安装包可安装；启动显示遮罩、后端随应用自动拉起；退出时优雅停机、无残留进程、端口无占用**；开发调试可选 Docker Compose 拉起 backend + ollama（数据层为 SQLite 单文件）。

## 9 附录：术语表
| 术语 | 说明 |
|---|---|
| 码字工具 | 产品本体定位：以写作体验为核心的桌面编辑器 |
| AI 赋能 | AI 作为写作辅助能力（续写/快捷处理/大纲灵感/素材/自检），非自动化流水线 |
| 续写 | 在光标处依据上文语境让 AI 继续生成正文，可撤销 |
| 快捷处理 | 对选中文字的扩写/精简/换风格/调篇幅，原地替换 |
| 文体 genre | 内容体裁枚举：NOVEL 网文 / MEDIA 自媒体 / OFFICIAL 公文 / CUSTOM 自定义 |
| ModelRouter | 模型路由层；统一适配 LOCAL(Ollama) 与 USER_PROVIDED_API 两种接入 |
| USER_PROVIDED_API | 用户自有第三方大模型 API，需联网，密钥仅单次请求内存 |
| LOCAL | 本地 Ollama 离线推理模式 |
| doc_version | 文档历史版本表；支撑对比与回滚 |
| material | 素材表；金句/案例按文体归档，可插入正文 |
| SSE | Server‑Sent‑Events 流式输出；本前端用 fetch + ReadableStream，禁用 EventSource |
| localStorage | 前端本地持久化；apiKey 与参数预设存于此，不上传后端 |
| Ollama | 本地模型运行服务；用户自行安装并下载预训练模型，应用不内置 |
| SQLite | 本机文件型嵌入式数据库；文档 / 版本 / 模板 / 素材以单文件落盘（WAL 模式），无需独立数据库服务 |
| TipTap | 基于 ProseMirror 的富文本编辑器内核；提供文档模型、撤销重做与稳定的位置映射，正文编辑器采用 |
| X‑Local‑Token | 后端启动生成的一次性本机接口令牌；写入 userData 文件由 Electron 主进程读取注入渲染进程，接口校验通过方可调用，**永不经过 HTTP 传输** |
| 数据目录 | Electron 以 `--writer.data-dir=<userData>/data` 指定的本地目录；存放 SQLite 库文件与 `agent.yml`，打包后仍可正确定位 |
