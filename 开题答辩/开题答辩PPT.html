一、选题背景与痛点Background & Pain Points

行业背景

大语言模型推动内容创作效率革命，网文 / 自媒体 / 公文等长文场景对 AI 写作辅助需求旺盛。

开源模型 + 本地推理工具（Ollama）成熟，"模型在本机、数据不出本机"成为可能。

Spring AI 1.0.0 GA 统一模型抽象与流式能力，Java 后端接入大模型门槛降低。

现实痛点

1在线 AI 写作工具强联网、正文上云，隐私风险突出、断网不可用。

2重"一键成文"、轻"写作体验"：防丢稿 / 版本 / 导出被忽视。

3本地模型门槛高，用户误把"下载模型"当"训练模型"。

4Java/Spring 栈在桌面 AI 写作中缺少端到端工程范例。

核心取舍：不做"多 Agent 自动化流水线"，聚焦"写得顺手的工具 + 随手可用的 AI"。

六、关键技术① 双模式模型接入 ModelRouterDual-mode Model Access

LOCAL · 本机 Ollama（离线隐私）

经 Spring AI 调用本机 Ollama；推理与文档全程留在本机，不出内网。

健康检测收敛为三状态：UNAVAILABLE 服务不可达 / MODEL_MISSING 服务连通但模型未下载 / READY 就绪；不可用时前端置灰引导。

USER_PROVIDED_API · 自有密钥（开箱即用）

用户自备 OpenAI 兼容接口，后端以 WebClient 直连并做 SSE 流式透传。

密钥随 POST 请求体传入，仅局部临时变量持有、请求结束即释放：不落库、不落日志、不经 HTTP 头传输、响应不回显。

前端请求 + modelConfig→ ModelRouter 路由判定→ LOCAL：Spring AI → Ollama/ API：WebClient → 第三方→ Flux 流 → SseEmitter → 前端插入
ModelRouter 为唯一大模型出入口；业务 Service 禁止直接新建 HTTP 客户端调用模型。

七、关键技术② 桌面进程编排与 Windows x64 交付Process Orchestration & Delivery

进程生命周期编排（R1）

主进程 spawn(java, {shell:false}) 直接拉起后端，使 java 成为直接子进程、kill 有效。

tree-kill（Windows 等价 taskkill /T /F）兜底杀整棵进程树。

启动前回收残留 8080；启动遮罩轮询健康接口；exit/close 非主动退出即崩溃自愈重启。

JVM ShutdownHook + 仅回环可访问的 shutdown 端点，退出先优雅停机、失败再强杀。

路径注入与零依赖交付（R7）

主进程以 --writer.data-dir=<userData>/data 注入数据目录。

Java 侧按"启动参数 → 环境变量 → user.home 兜底"解析；库文件 / agent.yml / 令牌文件全落该目录，禁止写死相对路径。

jlink 裁剪 JRE（约 50–90MB）打入 extraResources，用户无需预装 JDK21。

electron-builder 出 NSIS 安装包 + 免安装 zip；打包后冒烟测试不可省略。

启动→回收残留 8080→ spawn 后端→遮罩轮询就绪→ 显示编辑器→退出：shutdown → tree-kill

八、关键技术③ SSE 流式输出与资源释放SSE Streaming & Release

后端：SseEmitter 承载 + Disposable

用 SseEmitter（spring-boot-starter-web）承载，不引入 WebFlux。

订阅 Spring AI 返回的 Flux 时持有 Disposable，客户端断开即 dispose() 终止上游调用。

约 15s 心跳保活；心跳写失败即判定断连 → dispose，避免模型后台空跑与资源泄漏。

WebClient 显式连接 / 读超时；Broken pipe 优雅捕获。

前端：fetch + ReadableStream

禁用 EventSource，统一 fetch + ReadableStream 解析。

以 AbortController.abort() 主动取消请求。

SSE 事件严格白名单：token / error / complete，禁止白名单之外事件。

前端发起→Service 组装提示词→ ModelRouter → Flux→SseEmitter 逐块 token→ complete / 断连 dispose
白名单 | 心跳保活 | 写失败即释放，三重保障流式稳定性与资源不泄漏。

九、关键技术④ 本机接口纵深防御Local API Security

威胁模型：localhost 并非安全边界——恶意网页可通过 fetch / DNS rebinding 访问本机服务。v1.0 只防御浏览器网页发起的跨页攻击。

① X-Local-Token

后端启动生成一次性随机令牌，写入应用数据目录本地文件 → 主进程读取 → 经 preload 注入渲染进程。

业务接口强制校验请求头，不匹配返回 401；令牌永不经过 HTTP 传输、不入日志、不入 localStorage。

② Host 校验

仅允许 localhost / 127.0.0.1，拒绝其他 Host，防止 DNS rebinding 攻击。

后端仅绑定回环地址，禁止 0.0.0.0，严禁将 8080 暴露公网。

③ CORS 白名单

禁用 *，仅精确匹配生产 file://（Origin: null）与开发 http://localhost:5173。

安全基线：contextIsolation / sandbox 开启，nodeIntegration 关闭，CSP 收紧至仅 localhost:8080。

十、关键技术⑤ SQLite 并发与 offset 映射SQLite & Offset Mapping

SQLite 单写并发一致性

Hikari maximum-pool-size: 1 约束单写，避免 database locked。

连接初始化统一 PRAGMA：WAL / synchronous=NORMAL / busy_timeout=5000 / foreign_keys=ON。

红线：事务内禁止包裹网络 IO / AI 调用，禁止长事务长读；启动与定时 wal_checkpoint(TRUNCATE) 防 WAL 膨胀。

单进程独占；库文件即本地数据，备份只需复制。

全文自检 offset ↔ position 映射

自检偏移以纯文本投影（UTF-16 code unit）为基准，需映射到 ProseMirror position 才能标红 / 替换。

复用 TipTap / ProseMirror 稳定位置映射；替换经编辑器事务执行以进入撤销栈；替换后重取文本重建映射。

标红策略：仅手动点【全文自检】触发一次，用户编辑即清空标记，规避实时增量重算开销。

十一、功能模块一览Feature Modules

写作核心（工具本体 · P0）

• 编辑器：TipTap，标题 / 加粗 / 引用 / 列表，Markdown 快捷输入，实时字数

• 文档管理：新建 / 重命名 / 分组 / 搜索 / 删除，按时间排序与文体过滤

• 防丢稿：输入防抖实时自动缓存，崩溃 / 重启恢复并提示

• 版本留存：手动存版 + 会话结束自动存版，双版本 diff，一键回滚

• 多格式导出：txt / md / word（POI XWPF），按文体默认格式

• 舒适辅助：护眼暗色、悬浮字数（总字数 / 选中字数）

AI 赋能（保留项 · P1/P2）

• AI 续写：光标处依据上文流式续写，可撤销 / 重新生成

• 快捷处理：扩写 / 精简 / 换风格 / 调篇幅，原地替换可撤销

• 大纲与灵感：关键点生成结构化大纲、标题 / 开头 / 情节建议

• 素材收藏：选中收藏、按文体归档、点击 / 拖拽插入

• 全文自检：规则引擎（词级，必做）+ LLM 语义级（P2），标红替换

• 文体模板：网文 / 自媒体 / 公文一键切换

统一约定：AI 调用复用 ModelRouter；除自检外均流式返回；原地替换可撤销 / 可回退；不引入多 Agent 编排状态机。
